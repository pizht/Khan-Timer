# AGENTS.md

Guidance for AI agents and new maintainers working on Khan Academy Timer.

## What this project is

A Manifest V3 browser extension (Microsoft Edge, Chromium) that overlays a
per-question timer on Khan Academy exercises and quizzes. It detects the
question being solved, times it, and shows per-question times on the
end-of-exercise summary card.

`src/` and `dist/` are strictly separate: **Edge only ever loads the compiled
JavaScript in `dist/`**. `dist/` is generated by `pnpm run build`.

## Commands

```bash
pnpm install                 # first time only
pnpm run build               # build dist/
pnpm run typecheck           # tsc --noEmit, strict
pnpm run test                # vitest (offline)
pnpm run verify              # typecheck + test + build + verify-dist  <- offline gate
pnpm run verify:edge         # real Edge end-to-end against the LIVE site
pnpm run verify:startcard    # real Edge: start-card flash regression
pnpm run verify:practice-switch  # real Edge: switching practices
```

`pnpm run verify` is the gate you must pass before claiming anything works. It
is fully offline (no browser, no network).

The `verify:*` commands drive the **live** khanacademy.org and need a real
browser. They resolve Edge from `EDGE_PATH`, then platform defaults, then
`PATH` — see `scripts/lib/browser.mjs`.

## THE RULE: derive selectors from real DOM, never infer them

**This is the most important rule in this repository.**

Every selector, adapter rule and DOM assumption in `src/site-profile.ts` must be
derived from **markup actually observed on the live site**, not from:

- guessing at plausible attribute names,
- reasoning about what a React/Perseus app "probably" renders,
- copying selectors from other extensions, blog posts or model memory,
- extrapolating from a *different* Khan Academy page type without checking it.

The reason is not pedantry. The detector's correctness depends on facts that are
not knowable by inspection: which container is the question region, whether
hints render *inside* that region, whether the progress marker's state segment
changes when an answer is submitted, and whether a start card leaves a stale
question region behind. All of those were established by observation, and
several of them are counter-intuitive — see the regression block in
`tests/question-detector.test.ts`.

If a page type has not been observed, the correct outcome is to leave it
**unverified** (the extension degrades honestly and says it did not recognise
the question) — not to add a speculative selector. `docs/compatibility.md`
records what is actually verified, in tiers.

### How to get real DOM

```bash
# 1. Capture the live page (headless Edge, virtual-time budget, self-cleaning)
scripts/capture/capture-dom.sh dom <name> <url> new 25000
#    -> writes .tmp-caps/<name>.html  (raw, ~500 KB; NOT committed)

# 2. Reduce it to small, sanitised, structural excerpts
python3 scripts/capture/sanitize-snapshots.py \
    .tmp-caps/<name>.html .tmp-caps/out <label>
#    -> writes .tmp-caps/out/<label>-question-region.html, -exercise-footer.html,
#       -summary-screen.html, -feedback-dialog.html
```

Read those excerpts before writing or changing any selector. They are excerpts,
not whole pages: only the structural contract (classes, `name`, `role`,
`data-testid`, `aria-*`) is kept; scripts, styles and identifier-shaped values
are stripped.

For interactive questions ("what does the DOM look like *after* submitting an
answer?"), drive the page over CDP instead — see
`scripts/capture/cdp-probe.mjs` for the pattern, and prefer
`pnpm run verify:edge` when you need the extension loaded too.

### Sandbox notes (these cost real time to rediscover)

- Chromium's own sandbox cannot initialise inside a file sandbox, so
  `--no-sandbox` is **mandatory**; without it the GPU process dies and Edge
  aborts with `GPU process isn't usable. Goodbye.`
- Crashpad cannot write to `~/Library/Application Support`, so crash reporting
  must be redirected into the throwaway profile.
- `--dump-dom` never exits on a page with ongoing network activity; every run
  needs an explicit watchdog kill. `capture-dom.sh` already does this, which is
  why it is a script and not a one-liner.
- `$HOME` is not writable in a sandboxed agent session, so pnpm's content store
  falls back to `.pnpm-store` inside the project. That directory is a
  regenerable cache and is gitignored; delete it freely.

### When you change a selector

A selector change is not complete until:

1. the new value came from a capture of the **live** page (keep the excerpt
   under `.tmp-caps/` while you work, and paste the relevant markup into the
   commit message or PR description as evidence);
2. `pnpm run verify` passes — the unit tests encode the empirical regressions
   (submitting an answer must not reset the timer; opening a hint must not
   either);
3. `pnpm run verify:edge` passes against the live site;
4. `src/site-profile.ts` is still the **single** place selectors live. Do not
   scatter selectors into other modules.

Verify commands can be flaky because they drive a live third-party site that
changes without notice. A failure is evidence to investigate, not something to
retry blindly: distinguish "the site changed" (fix the selector) from "the
assertion is stale" (fix the assertion) before changing either.

## Caveats to keep in mind

- **This repository deliberately does not version captured DOM.** Raw captures,
  sanitised excerpts and screenshots all land in the gitignored `.tmp-caps/`.
  They go stale the moment Khan Academy ships a change, and a stale snapshot
  that still looks authoritative is worse than no snapshot. Re-capture instead
  (see "How to get real DOM" above) — that path is reproducible, and was
  verified byte-identical across captures taken days apart.
- `docs/research/` holds the **analysis** derived from live observation
  (page-type tiers, behaviour notes, why a selector was chosen). Analysis is
  not recoverable by re-capturing, which is why it *is* versioned. Capture dates
  are recorded inside each file; treat anything un-dated as historical.
- Some of the `scripts/capture/cdp-*.mjs` scripts are one-off investigation
  probes rather than polished tools; the maintained verification path is
  `scripts/verify-*.mjs`.
- The original requirements document cited by some docs as "需求文档第 N 节" is
  **no longer in this repository**. Treat those citations as historical
  context, not as a live contract.
- `docs/known-limitations.md` is the honest list of what is unverified or
  deliberately unsupported. Read it before promising a behaviour works.
