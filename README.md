# Khan Academy Timer

可汗学院（Khan Academy）练习题与测验的**题目计时**浏览器扩展。
Microsoft Edge（Chromium）+ Manifest V3 + TypeScript。

为当前题目自动计时，可靠识别切题，支持正计时 / 倒计时、暂停 / 继续 / 重置，
并在页面内显示一个不干扰答题的悬浮面板。所有数据只保存在本机。

> **本扩展不会**自动作答、自动提交、自动跳题，也不修改可汗学院的任何评分结果。
> 代码中**没有任何网络请求**（由 `npm run build` 后的自动检查强制保证）。

## 快速开始

需要 Node.js ≥ 20（开发时使用 v24）。本仓库使用 **pnpm**，
版本在 `package.json` 的 `packageManager` 中固定（`pnpm@12.11.2`），
启用 Corepack 后会自动使用该版本。

```bash
pnpm install
pnpm run build          # 生成可加载的 dist/
```

然后在 Edge 中加载 `dist/`（见下一节）。

一条命令跑完全部校验（类型检查 + 单元测试 + 构建 + 构建产物检查）：

```bash
pnpm run verify
```

## 功能

| 功能 | 说明 |
|---|---|
| **自动开始计时** | 检测到新题目后自动开始记录该题用时 |
| **正计时模式** | 显示已用时间，精度到秒 |
| **倒计时模式** | 按配置的每题限时倒计时，归零后进入明显的超时状态 |
| **超时提示音** | 可开关；用 Web Audio 现场合成，不加载任何音频文件 |
| **暂停 / 继续 / 重置** | 面板上的按钮，随时可用；暂停期间计时不累积 |
| **答对即停表** | Check 判定为正确后立刻停止本题计时（面板显示「已完成」），不会把思考后的发呆时间算进去 |
| **跳过即停表** | 在 Skip 的确认框里确认「Yes, skip」后停止本题计时；点 Cancel 则继续计时 |
| **切题自动结算** | 切题时保存上一题记录并自动开始新题计时 |
| **结束页显示每题用时** | 做完最后一题并点击 `Show summary` 后，在结束页注入「本轮每题用时」表格 |
| **第一次提交时间戳** | 记录第一次提交答案的时刻与其对错（需求 2.4） |
| **悬浮面板** | Shadow DOM 隔离，可拖动、可折叠为小胶囊，不遮挡答题区 |
| **历史记录** | 保存在本机，可查看最近记录、可一键清除 |
| **关闭页面后续接** | 重新打开同一题时，接着之前的用时继续计时 |
| **识别：未识别时暂停并隐藏面板** | 页面给不出可用的题目标识时（面板的「识别：未识别」）**不显示计时面板**，并把本题计时**暂停**；重新识别到**同一道题**时从暂停处继续，这段无法识别的时间不计入本题。已累计的用时与记录都保留，本题仍会出现在结束页的用时统计里 |

## 安装到 Edge

1. 构建（若还没构建）：

   ```bash
   pnpm install
   pnpm run build
   ```

   构建完成后会得到 `dist/` 目录，其中包含 `manifest.json`、编译后的 JavaScript、
   弹出面板页面与图标。**Edge 加载的是 `dist/`，不是 `src/`。**

2. 打开 Edge，地址栏输入 `edge://extensions` 回车。

3. 打开左下角（或左侧栏）的 **开发人员模式** 开关。

4. 点击 **加载解压缩的扩展**，选择本项目的 **`dist`** 目录。

5. 打开任意可汗学院练习页，例如：

   ```
   https://www.khanacademy.org/math/cc-third-grade-math/imp-addition-and-subtraction/imp-adding-with-regrouping-within-1000/e/addition_4
   ```

   右上角会出现「题目计时」悬浮面板，并自动开始正计时。

### 升级

改完代码后重新构建：

```bash
pnpm run build
```

然后到 `edge://extensions`，在扩展卡片上点击 **重新加载** 图标（↻），
再刷新可汗学院页面即可。**已保存的设置与计时记录会保留。**

### 卸载

到 `edge://extensions`，在扩展卡片上点击 **移除**。

如果还想清掉本机残留的数据：卸载会连同该扩展的 `chrome.storage.local` 一起删除。
也可以先打开弹出面板点击「清除全部记录」，再卸载。

## 设置说明

点击 Edge 工具栏上的扩展图标打开弹出面板。

| 设置项 | 默认值 | 说明 |
|---|---|---|
| **默认计时模式** | 正计时 | 新题开始时使用的模式。正计时记录用时；倒计时按限时倒数。 |
| **每题限时（秒）** | 60 | 倒计时模式的限时。允许 5–3600 秒。 |
| **倒计时归零时播放提示音** | 开 | 用 Web Audio 现场合成两声短音。若浏览器因未交互而阻止音频，会静默跳过并在面板说明。 |
| **在页面上显示悬浮面板** | 开 | 关闭后面板隐藏，仍在后台计时。 |
| **面板默认折叠为小胶囊** | 关 | 只显示一个计时数字，点击可展开。 |
| **关闭页面后重新打开时继续上次用时** | 开 | 见下方「时间语义」。 |
| **开发者模式** | 关 | 开启后才显示识别细节：弹出面板的识别方式、置信度、题目指纹、最近事件、诊断信息，以及悬浮面板的「识别：…」和页脚（最近事件、已记录条数）。 |
| **清除全部记录** | — | 只删记录，**不影响设置**。仅在 `已保存` 条数大于 0 时显示。 |

弹出面板始终显示当前页面的实时状态与**题目进度**；打开**开发者模式**后，
额外显示识别诊断（命中的选择器策略、识别置信度、题目指纹、最近事件、完整诊断文本），
便于判断某页面是否被可靠识别。

### 悬浮面板

- **拖动**：按住面板标题栏拖动。位置会保存。
- **折叠**：标题栏右侧的 `–` 按钮，折叠后只剩时间数字；点击胶囊展开。
- **暂停 / 继续**：中间的主按钮，按钮文字会切换。
- **重置本题**：只把**当前题**的计时归零，不影响其他题目或已保存记录。
- **开发者模式**：关闭时面板只显示时间、限时/超时、**题目进度**和操作按钮；
  开启后额外显示「识别：…」以及页脚的最近事件与「已记录 N」。
- 倒计时超时后面板变红并显示「超时 +已超出时间」，同时显示「限时 Ns」和题目进度。

### 什么时候显示计时面板

**面板只在真的给某道题计时时才出现**，与题目识别的状态同步（判据是「页面报出了题目
**位置**」+「不是未识别」+「引擎仍属于当前练习」，见下方说明）：

| 场景 | 面板 |
|---|---|
| 页面已确认某道题的**位置**（第几题）并开始计时 | **显示** |
| 课程目录页、视频页、任何没有题目的页面 | **不显示** |
| 测验 / 单元测试 / 课程挑战 / 练习的「开始卡片」（`Ready to practice?` / `Let’s go`） | **不显示**（还没有题目） |
| **切到另一个练习**（包括它自己的「Ready to practice?」开始卡片） | **不显示**（显示的是另一个练习的读数，已经暂存） |
| 练习结束页 | **不显示** |
| 题目识别失败（**识别：未识别**） | **不显示**，并且**暂停本题计时**（见下一节） |
| 已经开始计时，但页面结构临时变得无法识别 | **不显示**，并且**暂停本题计时**；重新识别到同一道题后自动继续 |

六点说明：

- 面板出现与消失都跟随「当前是否在**做题**」这一个判断，所以不会在不能计时的页面上
  显示一个量不出东西的时钟。
- **面板一开始就是隐藏的**：悬浮面板的宿主元素挂载时即为 `display:none`，只有检测
  到「确实在做某道题」时才由渲染循环打开。所以不存在「先默认显示、再发现没有题目
  又收起来」的那一瞬间——起始页上不会闪一下面板。
- **「做题中」的判据是页面报出了题目位置**（`exercise-progress-<第几题>`，或页面自己
  提供的题目 ID）：练习的起始页/过渡帧里往往还留着上一题的 Perseus 框架（`answerform`
  等），但它**没有位置**，所以不算「在做题」，面板不出现。作为代价，真实页面加载时
  题目区域（约 2.2 s）先于进度标记（约 3.7 s）出现，这几百毫秒到 1.5 秒内面板不显示，
  **但时钟已经在跑**，位置一到就显示当前读数——这段时间不会被丢掉，也不会被算到
  别处（见 `tests/controller.test.ts`「a question identified before its progress
  marker exists」两条）。
- 面板只显示**当前练习**的计时。可汗学院是单页应用，切换练习时地址变了但页面没
  重新加载；如果旧练习的计时器还留着，就会出现「在练习 B 的首页看到练习 A 的读数」
  并且那个读数还在继续涨。现在一旦页面属于另一个练习（或不属于任何练习），本题
  立即冻结并按下面的规则暂存。
- 「识别失败」时面板不显示、计时暂停，此时请打开**扩展弹出面板**查看原因与状态：
  它会显示「未找到题目区域」、实际命中的策略与错误列表，并明确写出
  「未识别到题目：本题计时已暂停，重新识别到本题后自动继续」；如果页面是
  「尚未开始」的介绍卡片，还会直接提示「尚未开始：请点击页面上的「Let's go」」。
- 弹出面板里的「在页面上显示悬浮面板」是总开关。关掉它则任何页面都不显示。

### 识别：未识别时会发生什么

页面不再给出可用的题目标识时（找不到题目区域，或区域里没有任何可用来区分题目的
信号），面板的「识别」一栏就是 **未识别**。此时：

1. **面板隐藏** —— 不再显示一个量不出东西的时钟；
2. **本题计时暂停** —— 这段无法识别的时间不会被算进这道题；
3. **引擎不丢弃，只是暂停** —— 已累计的用时、第一次提交时间戳、本轮 `runId` 全部保留；
4. 页面重新可识别且仍然是**同一道题**时，**从暂停处继续计时**（不是从零开始）；
5. 如果重新识别到的是**另一道题**，则按正常切题结算：暂停中的那道题照样写入记录，
   因此**在结束页的「本轮每题用时」里仍然有它的一行**。

暂停的这段时间会记在这道题的「暂停用时」里，所以在结束页那一行会看到
`用时 0:12` 加一行小字 `暂停 0:31`——用时与暂停用时是分开的，合计里只算用时。

只有**扩展自己**暂停的计时才会自动继续。学生手动点过「暂停」的题，识别恢复后
仍然保持暂停，不会被悄悄改成继续计时。

> 用一句话说明为什么这样更安全：**暂停**保留了引擎、累计用时和记录，只是让时钟
> 不再往前走；而**丢弃或重置**会让这道题在结束页里彻底消失。这条路径有单元测试
> 直接断言（见「测试与验证」中的 `tests/controller.test.ts`）。

### 什么时候计时会停止

| 情形 | 计时是否继续 | 说明 |
|---|---|---|
| 选中选项 / 在输入框里打字 | **继续** | 只是答题过程，不算做完 |
| 点 Check 但答**错** | **继续** | 还可以重试，计时不该中断 |
| 点 Check 且答**对** | **停止** | 面板变为「已完成」，数值冻结 |
| **答错后重答正确** | **停止** | 同上。可汗学院会把进度标记留在「第一次答错」，所以此处靠「Check 按钮被下一题控件取代」来判定 |
| 点 Skip 后点 **Cancel** | **继续** | 没有真的跳过 |
| 点 Skip 后确认 **Yes, skip** | **停止** | 面板显示已跳过 |
| **识别：未识别**（页面给不出可用的题目标识） | **暂停**（面板同时隐藏） | 重新识别到**同一道题**后自动继续；这段时间记入「暂停用时」，不计入本题用时，也不影响结束页的统计 |
| 倒计时归零 | 继续累计超时时间 | 显示超时状态，不自动提交、不自动跳题 |
| 进入下一题 / 结束页 | 结算并保存记录 | — |

答对或跳过后计时停止，但记录要等**题目真正切换**（或结束页出现）时才写入，
这样结束页才能拿到最后一题的用时。如果停表后又点了「重置本题」，
本题会重新开始计时。

> **一个容易踩的坑（已处理）：** 可汗学院的题目进度标记保留的是**第一次作答**的判定。
> 一道题先答错、再答对，标记会一直停在「答错」不变，**不会**变成「答对」。
> 如果只看这个状态，重答正确时计时永远不会停。所以实现同时使用两个信号：
> 状态字变为 `correct`（首次就答对，响应最快），以及 **Check 按钮被「下一题」控件取代**
> （任意一次答对，包含重答）。两者互补且幂等。详见
> [`references/observations.md`](references/observations.md) 第 11 节。

### 结束页的「本轮每题用时」

一轮练习（一次做完这套题的**全部**题目）结束后，`Show summary` 页面上会多出一张卡片。
下面是真实抓取到的输出（练习 `addition_4`，4 道题 + 1 道加试题）：

```
本轮每题用时                                        共 5 题 · 合计 0:19
──────────────────────────────────────────────────────────────────
题目                                                  用时
第 1 题  答对                                          0:04
第 2 题  已跳过                                        0:05
第 3 题  答对                                          0:03
第 4 题  答对                                          0:03
第 5 题  加试                                          0:03
```

卡片只有**两列**（题目、用时）。不显示计时模式列 —— 需要判断是否超时看
「超时」标记即可。若某一题中途暂停过（≥1 秒），会在用时下方以小字标注暂停时长。

**可以折叠。** 点标题行（或标题左侧的灰色箭头）即可收起明细，只剩标题与合计：

```
⌄  本轮每题用时                                        共 5 题 · 合计 0:19
────────────────────────────────────────────────────────────────────
题目                                                  用时
第 1 题  答对                                          0:04
第 2 题  已跳过                                        0:05
第 3 题  答对                                          0:03
第 4 题  答对                                          0:03
第 5 题  加试                                          0:03
```

折叠后（箭头由朝下转为朝右）：

```
›  本轮每题用时                                        共 5 题 · 合计 0:19
```

- 折叠状态会**记住**，下次打开结束页仍然是折叠的。
- 收起后标题与合计始终可见，随时点一下就能展开。
- 也可以用键盘操作：`Tab` 聚焦到箭头按钮后按 `Enter` / `空格`。
- **卡片按页面自己的视觉语言绘制**：方角、无阴影，**卡片自己只画一条顶部分隔线**
  （1px `#e1e1e1`，与页面自身的分隔线同色同宽）。左右与下边缘交给页面自己的边框与
  分隔线：之前卡片画了完整的四边框，正好叠在页面那几条线的旁边，于是左、右、下三条边
  都渲染成 2px，比 1px 的顶边粗一倍，看起来像「套在页面里的一个盒子」。卡片底边不留
  下边距，直接落在正文区上方的那条分界线上。折叠控件是标题左侧的灰色箭头
  （展开朝下、折叠朝右），不画方框、不填充底色。

- 只统计**这一轮**的题目；同一套练习重做时会开始新的一轮。
- **中途去别的练习做过题，不会影响这一轮。** 回到本练习把剩下的题做完后，切换之前
  已经做过的那几题仍然在表格里：题号、顺序、用时、对错标记都是原来的值，另一套练习的
  题目不会被混进来。
- 表格是**这套题的题号表**：每一行按**题目自己的题号**（页面进度索引 + 1）排列，
  而不是按记录落盘的先后顺位。每道题在开始计时的那一刻就把「属于哪个练习、第几题、
  本地题目指纹」写进记录，卡片再用**练习路由**（哪个练习）加本轮来取数，所以中途去过
  另一个练习也不会串行或错位。
- **某个题号没有计时数据时，那一行保留题号并标注「数据缺失」**（用时列显示 `—`），
  不会把下一题的用时顶上来。表头会写成「共 N 题 · M 题有数据 · 合计 …」。
- 同一题在一次练习里被计时了两段（中途离开练习又回来继续做）会**合并成一行**，
  用时是两段之和。
- 「答对」「答错」「已跳过」「超时」标记来自进度状态与第一次提交结果；
  索引倒退的那一行（可汗学院在「加试题」阶段会把索引重新从 0 开始）额外标记「加试」，
  并排在所有编号题目之后，因此不会出现两个「第 1 题」。
- 卡片同样使用 Shadow DOM 隔离，不会影响也不受可汗学院样式影响。
- **卡片只在真正的结束页出现。** 除了结构判据（无答题表单、无进度点、有练习外壳），
  还要求「刚刚做完一道题」（结束页必然承接一道已停表的题）与「当前地址仍属于本轮记录
  所属的那个练习」；一旦页面上出现「Ready to practice?」介绍卡片，卡片会立刻被撤掉。
  这三条一起挡掉了「介绍页/过渡帧被误判成结束页」的情况。
- **卡片不会遮住页面上任何原有内容。** 它插在练习内容区之前，把内容向下推，
  因此「Exercise complete!」「4/4 correct」「Course mastery」「Try again」
  「Up next」等原有信息都完整可见。这一点是通过在真实结束页上测量卡片与页面文本的
  重叠数量确定的（最终实测：**0 处重叠**），而不是靠猜类名 —— 细节见
  [`references/observations.md`](references/observations.md) 第 10.7 节。
- 数据只来自本机存储，不发起任何网络请求。

> **注意：** 只有把整套题做完（在 `Show summary` 上）才会出现这张卡片。
> 如果练习有 bonus question，要先做完加试题才会看到 `Show summary`。

### 时间语义（重要）

| 情形 | 行为 |
|---|---|
| 标签页切到后台，或电脑休眠（**页面仍开着**） | 按**真实经过时间**计算。恢复显示时按时间戳重算，不依赖定时器触发次数。 |
| 手动点击「暂停」 | 停止累积；「继续」后从暂停时的数值接着走。 |
| **关闭页面后重新打开同一题** | 关闭期间的时钟**冻结**，恢复已累计的用时继续计时。理由：关闭页面时学生并没有在作答。 |
| **切到另一个练习（或课程页、视频页）后回来** | 同上：离开期间的时钟**冻结**。回到同一道题时接着已累计的用时继续；切题、做完整轮或换练习都不会丢掉已记录的用时。 |

关闭页面或离开练习期间的会话会以 `session:<练习路径>` 的形式保存在本地，超过 **12 小时**后丢弃。
只有当**练习和题目都匹配**时才会续接，且**每个练习各存一份**：在练习 A 做到一半去
练习 B，A 的那份会话会原样留着；回到 A 的同一道题时从离开时的读数继续，不会从 0 开始，
也不会把在 B 花的时间算进 A。

已经**答对或跳过**的那道题在离开时会立刻落盘（否则它会一直等一个永远不来的「切题」），
所以「已经做过的题目」的用时在切换练习后仍然保留，并计入本轮结束页。

**回到练习后做完剩下的题，结束页是完整的。** 本轮（一次做完这套题）的记录以同一个
`runId` 归组：换练习不会开始新的一轮。取数时先按**练习路由**（记录里的
`exerciseKey`，即「哪一套题」）过滤，再收到本轮 —— 别的练习的记录不可能出现在这张卡片上，
即使 runId 撞了或丢了也不会。于是 A 的结束页仍然按**题号**列出切换前那几题，
用时、答对/答错/跳过/超时标记都是原值；某个题号没有数据就写「数据缺失」，
不会把下一题的用时顶到它的题号上。

卡片取数有三层，且都不依赖某一轮 id 的稳定：练习路由 → **本次尝试窗口**
（`attempt:<练习路径>`，每道题开始时开启，只有真的看过结束页才推进）→ `runId`。
所以「切换练习前做过的那几题」即使本轮 id 中途丢了也能被重新检索到，不会再显示成
「数据缺失」——记录一直都在本地 `records` 里，丢的只是归属。

记录落盘走的是**单条串行队列**（`createRecordQueue`）：`records` 的写入是
「读出来 → 追加 → 写回」，而 `chrome.storage` 没有事务，两次并发写入会让后写的把
前一条覆盖掉（结束页就少一行）。所有写入串到一条链上，结束页在读取前会先等这条链
排空，所以那一行不会因为一次争用而消失。

> **曾经的问题（已修复）：** 可汗学院是单页应用，切换练习只换地址不重新加载页面。
> 那时旧练习的计时器不会被收掉——面板会带着旧读数继续涨，新练习的第一题又常常和旧
> 练习停在同一进度（都是「1 of N」），于是被当成「题目没变」，旧练习那份进行中的
> 会话被当成一次普通切题结算掉；等回到旧练习时，已累计的用时已经没了。

## 本地数据与清除

所有数据都在 `chrome.storage.local`（浏览器本地），**不上传任何服务器**。

| 键 | 内容 |
|---|---|
| `settings` | 上表中的全部设置 + 悬浮面板的位置/折叠状态 + 结束页用时卡片的折叠状态（`summaryCollapsed`，默认展开）。 |
| `records` | 计时记录数组，**最多保留最近 500 条**，超出丢弃最旧的。 |
| `session:<练习路径>` | 进行中的题目会话（关闭页面、切换练习时暂存，每个练习一份）；超过 12 小时自动清理。 |

**记录里包含**：题目在练习中的位置、本地题目指纹、练习路径、开始/结束时刻、
用时、暂停时长、是否超时、第一次提交的时刻与对错、结束原因、识别置信度。

**记录里不包含**：题目原文、你输入的答案、账号信息，或任何与计时无关的数据。
题目文本只在内存中临时用于生成本地指纹（一个 8 位十六进制短哈希），**不落盘**。

### 清除

- 打开弹出面板 → **清除全部记录**。这只会删掉 `records`，设置保持不变。
  记录为 `已保存 0 条` 时该按钮不显示，因为没有可清除的内容。
  结果（`记录已清除`，或存储不可用时的失败原因）显示在**同一张「历史记录」卡片内**、
  按钮下方，约 1.6 秒后消失；设置卡片只在设置写入失败时提示。
- 想连设置一起重置：在弹出面板把各项调回默认值，或卸载后重新加载扩展。

### 查看

弹出面板底部的「历史记录」区域会列出最近 10 条，包含用时、模式、是否超时、
第一次提交的结果与题目短标识。

## 开发

```bash
pnpm install

pnpm run build          # 一次性构建到 dist/
pnpm run build:watch     # 监听源码变化自动重建
pnpm run typecheck       # tsc --noEmit，严格模式
pnpm run test            # vitest run
pnpm run test:watch      # vitest 监听
pnpm run icons           # 从 assets/logo.png 重新生成图标 PNG
pnpm run verify          # typecheck + test + build + dist 检查
pnpm run verify:edge     # 真实 Edge 端到端验证（67 项）
pnpm run verify:all      # 上面两个一起跑
```

`src/` 与 `dist/` 严格分离：**Edge 只加载 `dist/` 里编译后的 JavaScript**。

构建**刻意不做压缩**，并同时输出 source map。这样需求 8.4「代码审查确认没有计时数据
上传」可以直接对着 `dist/*.js` 人工审查。

### Logo 与图标

项目 logo 的原图是 [`assets/logo.png`](assets/logo.png)（满幅蓝底方形，1254×1254，
图案为学士帽 + 秒表 + 树叶 + 黄色提速射线）。`pnpm run icons` 会用 Lanczos-3 把它
重采样为 16/32/48/128 px，输出到 `public/icons/`，构建时再复制进 `dist/`——**没有引入
任何图像处理依赖**，脚本只用 Node 内置的 `zlib` 解压/压缩 PNG。

图标按原图外形生成**满幅直角方形、完全不透明**。脚本开头会先校验原图仍是「方形、蓝底
铺满四边、四角也是蓝色」，所以如果 logo 被换成带白底或圆角的旧式素材，`pnpm run icons`
会直接报错而不是悄悄产出一张裁错的图。

### 2.5 真实站点上复现「切换练习」（`scripts/verify-practice-switch.mjs`）

`scripts/verify-extension.mjs` 验证的是单个练习的完整交互。这个脚本验证**你的操作**：
在真实 khanacademy.org 上开练习 A、答两题、切到练习 B 答一题、回到 A 做完，
然后读结束页卡片（Shadow DOM）与 `chrome.storage.local`（通过扩展自身的 popup 页面）。

```bash
node scripts/verify-practice-switch.mjs                     # A/B 用内置的两个练习
node scripts/verify-practice-switch.mjs <urlA> <urlB> --switch=spa
node scripts/verify-practice-switch.mjs --profile=/tmp/kat-profile --headed   # 手动登录一次
node scripts/verify-practice-switch.mjs --profile=/tmp/kat-profile            # 之后无头重跑
```

- **不需要登录**就能跑「换练习不串味」的部分（两个练习各自计时、记录分别归属）。
- 但**结束页卡片只有登录后才有**：匿名用户做完练习后，可汗学院把它换成
  「Log in or Sign up to save your future progress!」，既不是题目区域也不是结束页，
  扩展不会（也不该）在那里插卡片。
- 登录只做一次：`--login --profile=/tmp/kat-login` 会打开一个**可见窗口**停在登录页，
  脚本每 2 s 检查一次，检测到「已登录的 khanacademy.org 页面稳定 5 s」后自己继续。
  之后复用同一 profile 时，脚本会先把它的 **khanacademy.org cookies 读出来注入一个
  全新 profile**（已登录的 profile 里 Edge 会把我们的未打包扩展标记成 disabled，
  换个新 profile 才能加载扩展；见 `docs/known-limitations.md` 第 26 条）。
  `--switch=link` 用课程侧栏里的链接切换练习，也就是真实的应用内路由切换。
- 这个脚本已经在真机上抓到并复现了两个真实缺陷：进度标记晚到被当成切题
  （见「题目识别」一节的身份升级用例），以及**切换练习时旧练习被误判为结束页**
  （见已知限制第 27 条）。修好之后，真机跑完的结果是：练习 A 的结束页卡片列出**全部 4 道题**
  各自的用时，两段（切换前 / 切换后）的记录属于**同一次尝试**，练习 B 的记录不会混进来。

### 4. 手动验证「识别：未识别 → 暂停 → 恢复」

真实 Edge 上无法稳定制造这一幕，所以这一条请手动走一遍。
在任意练习页（先让面板出现并计时几秒）打开 DevTools Console：

```js
// 1) 观察当前状态：unidentified=false，autoPausedForIdentity=false，enginePhase="running"
const host = document.getElementById('khan-academy-timer-host');
const read = () => JSON.parse(host.getAttribute('data-khan-timer-diagnostics'));
console.table(read());

// 2) 记住并移除题目区域（把三种候选选择器都移除，模拟「页面读不出题目」）
const removed = [...document.querySelectorAll(
  'form[name="answerform"], .framework-perseus, .perseus-renderer',
)].map((el) => [el.parentNode, el, el.nextSibling]);
removed.forEach(([, el]) => el.remove());
// 约 0.7 s 后面板消失（弹出面板同时显示「未识别到题目：本题计时已暂停，
// 重新识别到本题后自动继续」）：
//   read() → { unidentified: true, autoPausedForIdentity: true, enginePhase: "paused" }
await new Promise((r) => setTimeout(r, 5000));   // 这 5 秒不应计入本题

// 3) 把同一个题目区域原样放回（还是同一道题，进度标记一动没动）
removed.reverse().forEach(([parent, el, next]) => parent.insertBefore(el, next));
// 面板立即（毫秒级）重新出现：
//   read() → { unidentified: false, autoPausedForIdentity: false, enginePhase: "running" }
// 面板读数从暂停时的数值继续，而不是从 0:00 重新开始
```

用时不含第 2 步等待的 5 秒；如果暂停超过 1 秒，那一行还会多出一行小字
`暂停 0:05`。

> 同样的字段（`unidentified` / `autoPausedForIdentity` / `enginePhase`）由
> `tests/controller.test.ts` 自动断言，所以上面的手动步骤与单元测试检查的是同一件事。

## 题目识别原理

这一节解释「为什么这样识别」，完整的实测证据见 `references/`。

### 题目区域

优先取 `form[name="answerform"]`（Perseus 渲染器把整道题都放在这个表单里），
依次降级到 `.framework-perseus`、`.perseus-renderer`。

实测（真实页面、真实答题）：**提交答案前后，该区域的文本逐字节相同**，
答对/答错的反馈浮层是它的**兄弟节点**而非子节点，因此答题反馈不会干扰识别。

### 题目标识 = 题目进度索引

练习页底部每个进度点带一个 testid：

```
exercise-progress-<索引>-<状态>[-current]
```

实测结论：

- **索引**在切题时变化（`0 → 1 → 2 → 3`）；
- **状态**（`incomplete` / `correct` / `incorrect`）在**提交答案时**变化。

所以身份只取**索引**。如果把整个 testid 当身份，学生每提交一次答案就会被判定为换题。
站点**不提供**单题稳定 id（`data-question-id` 等全部 0 次匹配），因此这是最强可用信号。

若页面没有进度标记（未验证的页面类型），降级为「题干文本 + 题型签名」的哈希指纹，
并把置信度标为较低，面板会显示出来。

### 提示与解答不会重置计时

实测发现：展开提示/分步解答时，内容会渲染**在题目区域内部**，区域文本从 3,466 字符
暴涨到 22,910 字符，但**进度索引没有变化**。

由于身份是索引，这种情况天然不会误判。这一点已写成回归测试长期锁定。
（另外 `[role="dialog"]` / `[role="alert"]` / `[aria-live]` 会从指纹中剔除作为冗余防护。）

### 去抖与重复抑制

新身份必须**连续稳定 400 ms**、且距上一次已接受的切换**至少 1200 ms**，才会被接受。
同一道题只会有一次切换事件，因此不会产生重复记录或多重计时器。
候选出现后检测器会主动安排一次延后复核来确认它 —— 这个「第二次观察」是必须的，
否则候选会永远停在待确认状态（这正是真实页面验证抓出来的缺陷之一）。

### 识别：未识别时的行为

找不到题目区域、或没有任何可用身份信号时：

1. 发出 `uncertain` 事件；
2. **暂停**当前这道题的计时（**不重置、不丢弃**：引擎保留，累计用时、第一次提交
   时间戳与本轮 `runId` 都在）；
3. **隐藏**悬浮面板；
4. 扩展弹出面板给出可见提示：状态行显示
   `未识别到题目：本题计时已暂停，重新识别到本题后自动继续`，警告区显示
   `无法可靠识别当前题目（<原因>）。本题计时已暂停，重新识别到本题后会自动继续。`；
   页内这条警告**只在面板可见时**渲染，并且**随识别恢复一起清除**——它描述的只是
   「页面读不出题目的那一段」，不会留在一个正在计时的面板上；
5. 只有**同一道题**重新可识别时才自动继续计时；识别到的是另一道题，就走正常切题
   结算，被暂停的那道题照样落盘，因此仍然出现在结束页的用时统计里；
6. 学生手动按下的「暂停」不会被自动继续。

> 早期实现是「保持计时不变」。改成暂停是因为：页面读不出题目时，时钟继续走会把
> 这段时间算到这道题上。暂停既保住了已有数据，又不把读不出的时间计进用时。

### 显式重置信号

- **URL 变化**：清空识别状态，按新页面重新开始。
- **点击「Start over」**：视为该题被就地重新生成，强制开始新题计时
  （因为索引不变，自动检测无法发现这种情况）。

## 故障排查

### 面板没有出现

1. 确认当前页面的域名是 `khanacademy.org`（扩展只在这些域名注入）。
2. 到 `edge://extensions` 确认扩展已启用，且**没有报错**。
3. 确认地址是**练习页**（URL 里含 `/e/`、`/quiz/` 或 `/test/`）。
   课程目录页、视频页没有题目区域，因此不会显示面板。
4. 确认**题目已经出现**：面板要等页面报出「第几题」（`exercise-progress-*`）才显示，
   所以练习/测验的起始卡片（`Ready to practice?` / `Let's go`）上不会出现面板。
   刚打开题目后的几百毫秒内也可能还没显示 —— 那时**计时已经在跑**，位置一到就把
   已经累计的读数显示出来。
5. 刷新页面（内容脚本在页面加载后注入）。
6. 打开弹出面板看诊断信息：若「当前状态」显示「未找到题目区域」，
   说明该页面结构尚未适配。
   如果你本来就在做题、面板却突然消失，请看下一条。

### 面板突然消失，或出现「识别：未识别」

这是**预期行为**，不是崩溃：页面此刻没有给出可用的题目标识（面板的「识别」一栏
是「未识别」），所以扩展**隐藏了面板并暂停了本题计时**，这段读不出来的时间不会被
算进这道题。已经累计的用时没有丢，本题的记录也仍然会出现在结束页的用时统计里。
打开扩展弹出面板会明确写出「未识别到题目：本题计时已暂停，重新识别到本题后自动继续」。

通常它会在页面重新渲染出题目后自动恢复：**同一道题**回来就从暂停处继续，
换成**另一道题**就正常结算。如果长时间不恢复，说明该页面结构与已验证的练习页不同；
请打开弹出面板的**开发者模式**，把「诊断信息」里的内容
（命中的策略、错误列表）反馈出来。

> 页面上那条 `无法可靠识别当前题目（question region not found）。…` **只在页面确实
> 读不出题目、且面板可见时**出现，识别恢复后会自动消失。若你看到「面板正在计时（`暂停`
> 按钮、秒数在走）却同时挂着这条警告」，那是旧构建的缺陷（警告没有随恢复清除）；
> 重新加载 `dist/` 后即不会再出现。想确认页面的真实状态，可在 DevTools 控制台执行：
>
> ```js
> JSON.parse(document.getElementById('khan-academy-timer-host')
>   .getAttribute('data-khan-timer-diagnostics'))
> ```
>
> 其中 `unidentified: true` 才表示「此刻确实读不出题目」。

### 切题后计时没有重置

1. 打开弹出面板的**开发者模式**，看「置信度」。如果是「弱信号」或「未识别」，
   说明该页面没有可用的进度标记。
2. 确认页面底部确实有题目进度点（`Do N problems` 旁边的圆点）。
3. 如果该练习是「Start over」后重新生成的，点击「重置本题」也可手动开始新计时。

### 换到另一个练习后，回来发现这道题的用时是从一半开始的

这是有意的（见「时间语义」）：离开练习时本题会**冻结并暂存**，回来后接着已累计的
用时继续，离开期间不计入。想从零开始就点「重置本题」。
如果「回来时用时归零」，那说明会话被当成别的题目处理了 —— 请打开弹出面板把
「练习路径」和「题目指纹」记下来反馈。切换练习的完整行为与边界条件见
[`docs/known-limitations.md`](docs/known-limitations.md) 第 22 条。

### 倒计时没有声音

浏览器会在用户与页面交互之前阻止音频播放。点击页面任意位置后再试。
面板会在页脚说明提示音被阻止。

### `pnpm run test` 报 Rollup 原生模块加载失败

症状：

```
Error: Cannot find module @rollup/rollup-<platform>
...
ERR_DLOPEN_FAILED ... different Team IDs
```

原因：Vitest 依赖的 Rollup 会加载平台原生模块，而某些环境（例如 Node 二进制以
macOS **hardened runtime** 签名运行）会因签名 Team ID 不同而拒绝加载该模块。

本仓库已在 `pnpm-workspace.yaml` 中把 `rollup` 覆盖为**纯 WebAssembly 版本**
（`@rollup/wasm-node`），API 完全一致且不依赖原生模块，因此默认不会有这个问题。

如果不小心装回了原生版本：

```bash
rm -rf node_modules pnpm-lock.yaml
pnpm install
```

（若你确实希望使用原生 Rollup —— 例如在不受该签名限制的环境里追求速度 ——
删掉 `pnpm-workspace.yaml` 中的 `overrides` 一段再重装即可。）

### `pnpm run build` 之后 Edge 里没有变化

Edge 不会自动感知 `dist/` 的变化。到 `edge://extensions` 点击扩展卡片上的
**重新加载** 图标，然后刷新可汗学院页面。

### 不想让它记录我的练习数据

- 计时记录只存在本机，永远不会上传（可用 `node scripts/verify-dist.mjs` 复核）。
- 用弹出面板的「清除全部记录」随时删除。
- 也可以关闭「关闭页面后重新打开时继续上次用时」，这样就不会写入进行中的会话。
