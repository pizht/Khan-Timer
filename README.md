# Khan Academy Timer

可汗学院（Khan Academy）练习题与测验的**题目计时**浏览器扩展。
Microsoft Edge（Chromium）+ Manifest V3 + TypeScript。

为当前题目自动计时，可靠识别切题，支持正计时 / 倒计时、暂停 / 继续 / 重置，
并在页面内显示一个不干扰答题的悬浮面板。所有数据只保存在本机。

> **本扩展不会**自动作答、自动提交、自动跳题，也不修改可汗学院的任何评分结果。
> 代码中**没有任何网络请求**（由 `npm run build` 后的自动检查强制保证）。

## 快速开始

需要 Node.js ≥ 20（开发时使用 v24）。本仓库使用 **pnpm**，
版本在 `package.json` 的 `packageManager` 中固定（`pnpm@12.11.2`），
启用 Corepack 后会自动使用该版本。

```bash
pnpm install
pnpm run build          # 生成可加载的 dist/
```

然后在 Edge 中加载 `dist/`（见下一节）。

一条命令跑完全部校验（类型检查 + 单元测试 + 构建 + 构建产物检查）：

```bash
pnpm run verify
```

## 功能

| 功能 | 说明 |
|---|---|
| **自动开始计时** | 检测到新题目后自动开始记录该题用时 |
| **正计时模式** | 显示已用时间，精度到秒 |
| **倒计时模式** | 按配置的每题限时倒计时，归零后进入明显的超时状态 |
| **超时提示音** | 可开关；用 Web Audio 现场合成，不加载任何音频文件 |
| **暂停 / 继续 / 重置** | 面板上的按钮，随时可用；暂停期间计时不累积 |
| **答对即停表** | Check 判定为正确后立刻停止本题计时（面板显示「已完成」），不会把思考后的发呆时间算进去 |
| **跳过即停表** | 在 Skip 的确认框里确认「Yes, skip」后停止本题计时；点 Cancel 则继续计时 |
| **切题自动结算** | 切题时保存上一题记录并自动开始新题计时 |
| **结束页显示每题用时** | 做完最后一题并点击 `Show summary` 后，在结束页注入「本轮每题用时」表格 |
| **第一次提交时间戳** | 记录第一次提交答案的时刻与其对错（需求 2.4） |
| **悬浮面板** | Shadow DOM 隔离，可拖动、可折叠为小胶囊，不遮挡答题区 |
| **本地记录** | 保存在本机，可查看最近记录、可一键清除 |
| **关闭页面后续接** | 重新打开同一题时，接着之前的用时继续计时 |
| **识别不确定时保守降级** | 保持计时不变并给出可见提示，绝不静默乱重置 |

## 安装到 Edge

1. 构建（若还没构建）：

   ```bash
   pnpm install
   pnpm run build
   ```

   构建完成后会得到 `dist/` 目录，其中包含 `manifest.json`、编译后的 JavaScript、
   弹出面板页面与图标。**Edge 加载的是 `dist/`，不是 `src/`。**

2. 打开 Edge，地址栏输入 `edge://extensions` 回车。

3. 打开左下角（或左侧栏）的 **开发人员模式** 开关。

4. 点击 **加载解压缩的扩展**，选择本项目的 **`dist`** 目录。

5. 打开任意可汗学院练习页，例如：

   ```
   https://www.khanacademy.org/math/cc-third-grade-math/imp-addition-and-subtraction/imp-adding-with-regrouping-within-1000/e/addition_4
   ```

   右上角会出现「题目计时」悬浮面板，并自动开始正计时。

### 升级

改完代码后重新构建：

```bash
pnpm run build
```

然后到 `edge://extensions`，在扩展卡片上点击 **重新加载** 图标（↻），
再刷新可汗学院页面即可。**已保存的设置与计时记录会保留。**

### 卸载

到 `edge://extensions`，在扩展卡片上点击 **移除**。

如果还想清掉本机残留的数据：卸载会连同该扩展的 `chrome.storage.local` 一起删除。
也可以先打开弹出面板点击「清除全部记录」，再卸载。

## 设置说明

点击 Edge 工具栏上的扩展图标打开弹出面板。

| 设置项 | 默认值 | 说明 |
|---|---|---|
| **默认计时模式** | 正计时 | 新题开始时使用的模式。正计时记录用时；倒计时按限时倒数。 |
| **每题限时（秒）** | 60 | 倒计时模式的限时。允许 5–3600 秒。 |
| **倒计时归零时播放提示音** | 开 | 用 Web Audio 现场合成两声短音。若浏览器因未交互而阻止音频，会静默跳过并在面板说明。 |
| **在页面上显示悬浮面板** | 开 | 关闭后面板隐藏，仍在后台计时。 |
| **面板默认折叠为小胶囊** | 关 | 只显示一个计时数字，点击可展开。 |
| **关闭页面后重新打开时继续上次用时** | 开 | 见下方「时间语义」。 |
| **清除全部记录** | — | 只删记录，**不影响设置**。 |

弹出面板同时显示当前页面的实时状态与识别诊断（命中的选择器策略、识别置信度、
题目指纹、最近事件、完整诊断文本），便于判断某页面是否被可靠识别。

### 悬浮面板

- **拖动**：按住面板标题栏拖动。位置会保存。
- **折叠**：标题栏右侧的 `–` 按钮，折叠后只剩时间数字；点击胶囊展开。
- **暂停 / 继续**：中间的主按钮，按钮文字会切换。
- **重置本题**：只把**当前题**的计时归零，不影响其他题目或已保存记录。
- 倒计时超时后面板变红并显示「超时 +已超出时间」，同时显示「限时 Ns」和题目进度。

### 什么时候显示计时面板

**面板只在真的给某道题计时时才出现**，与题目识别的状态同步：

| 场景 | 面板 |
|---|---|
| 识别到题目并开始计时 | **显示** |
| 课程目录页、视频页、任何没有题目的页面 | **不显示** |
| 测验 / 单元测试 / 课程挑战的「开始卡片」（`Let’s go`） | **不显示**（还没有题目） |
| 练习结束页 | **不显示** |
| 题目识别失败（未识别） | **不显示** |
| 已经开始计时，但页面结构临时变得无法识别 | **显示**（保留暂停/重置，避免一闪就不见） |

三点说明：

- 面板出现与消失都跟随「当前是否在计时」，所以不会在不能计时的页面上显示一个
  量不出东西的时钟。
- 「识别失败」时面板不显示，此时请打开**扩展弹出面板**查看原因：它会显示
  「未找到题目区域（此页面暂不支持）」、实际命中的策略与错误列表；如果页面是
  「尚未开始」的介绍卡片，还会直接提示「尚未开始：请点击页面上的「Let's go」」。
- 弹出面板里的「在页面上显示悬浮面板」是总开关。关掉它则任何页面都不显示。

### 什么时候计时会停止

| 情形 | 计时是否继续 | 说明 |
|---|---|---|
| 选中选项 / 在输入框里打字 | **继续** | 只是答题过程，不算做完 |
| 点 Check 但答**错** | **继续** | 还可以重试，计时不该中断 |
| 点 Check 且答**对** | **停止** | 面板变为「已完成」，数值冻结 |
| **答错后重答正确** | **停止** | 同上。可汗学院会把进度标记留在「第一次答错」，所以此处靠「Check 按钮被下一题控件取代」来判定 |
| 点 Skip 后点 **Cancel** | **继续** | 没有真的跳过 |
| 点 Skip 后确认 **Yes, skip** | **停止** | 面板显示已跳过 |
| 倒计时归零 | 继续累计超时时间 | 显示超时状态，不自动提交、不自动跳题 |
| 进入下一题 / 结束页 | 结算并保存记录 | — |

答对或跳过后计时停止，但记录要等**题目真正切换**（或结束页出现）时才写入，
这样结束页才能拿到最后一题的用时。如果停表后又点了「重置本题」，
本题会重新开始计时。

> **一个容易踩的坑（已处理）：** 可汗学院的题目进度标记保留的是**第一次作答**的判定。
> 一道题先答错、再答对，标记会一直停在「答错」不变，**不会**变成「答对」。
> 如果只看这个状态，重答正确时计时永远不会停。所以实现同时使用两个信号：
> 状态字变为 `correct`（首次就答对，响应最快），以及 **Check 按钮被「下一题」控件取代**
> （任意一次答对，包含重答）。两者互补且幂等。详见
> [`references/observations.md`](references/observations.md) 第 11 节。

### 结束页的「本轮每题用时」

一轮练习（一次做完这套题的**全部**题目）结束后，`Show summary` 页面上会多出一张卡片。
下面是真实抓取到的输出（练习 `addition_4`，4 道题 + 1 道加试题）：

```
本轮每题用时                                        共 5 题 · 合计 0:19
──────────────────────────────────────────────────────────────────
题目                                                  用时
第 1 题  答对                                          0:04
第 2 题  已跳过                                        0:05
第 3 题  答对                                          0:03
第 4 题  答对                                          0:03
第 5 题  加试                                          0:03
```

卡片只有**两列**（题目、用时）。不显示计时模式列 —— 需要判断是否超时看
「超时」标记即可。若某一题中途暂停过（≥1 秒），会在用时下方以小字标注暂停时长。

**可以折叠。** 点标题行（或左侧的 `▾` 按钮）即可收起明细，只剩标题与合计：

```
本轮每题用时                    ▾        共 5 题 · 合计 0:19
────────────────────────────────────────────────────────────
题目                                                  用时
第 1 题  答对                                          0:04
第 2 题  已跳过                                        0:05
第 3 题  答对                                          0:03
第 4 题  答对                                          0:03
第 5 题  加试                                          0:03
```

折叠后：

```
本轮每题用时                    ▸        共 5 题 · 合计 0:19
```

- 折叠状态会**记住**，下次打开结束页仍然是折叠的。
- 收起后标题与合计始终可见，随时点一下就能展开。
- 也可以用键盘操作：`Tab` 聚焦到 `▾` 按钮后按 `Enter` / `空格`。

- 只统计**这一轮**的题目；同一套练习重做时会开始新的一轮。
- 表格**按答题顺序编号**，而不是用页面自己的进度索引。原因是可汗学院在
  「加试题」阶段会把索引重新从 0 开始，用索引编号会让表格里出现两个「第 1 题」。
- 「答对」「答错」「已跳过」「超时」标记来自进度状态与第一次提交结果；
  索引倒退的那一行额外标记「加试」。
- 卡片同样使用 Shadow DOM 隔离，不会影响也不受可汗学院样式影响。
- **卡片不会遮住页面上任何原有内容。** 它插在练习内容区之前，把内容向下推，
  因此「Exercise complete!」「4/4 correct」「Course mastery」「Try again」
  「Up next」等原有信息都完整可见。这一点是通过在真实结束页上测量卡片与页面文本的
  重叠数量确定的（最终实测：**0 处重叠**），而不是靠猜类名 —— 细节见
  [`references/observations.md`](references/observations.md) 第 10.7 节。
- 数据只来自本机存储，不发起任何网络请求。

> **注意：** 只有把整套题做完（在 `Show summary` 上）才会出现这张卡片。
> 如果练习有 bonus question，要先做完加试题才会看到 `Show summary`。

### 时间语义（重要）

| 情形 | 行为 |
|---|---|
| 标签页切到后台，或电脑休眠（**页面仍开着**） | 按**真实经过时间**计算。恢复显示时按时间戳重算，不依赖定时器触发次数。 |
| 手动点击「暂停」 | 停止累积；「继续」后从暂停时的数值接着走。 |
| **关闭页面后重新打开同一题** | 关闭期间的时钟**冻结**，恢复已累计的用时继续计时。理由：关闭页面时学生并没有在作答。 |

关闭页面期间的会话会以 `session:<练习路径>` 的形式保存在本地，超过 **12 小时**后丢弃。
只有当**练习和题目都匹配**时才会续接。

## 本地数据与清除

所有数据都在 `chrome.storage.local`（浏览器本地），**不上传任何服务器**。

| 键 | 内容 |
|---|---|
| `settings` | 上表中的全部设置 + 悬浮面板的位置/折叠状态 + 结束页用时卡片的折叠状态（`summaryCollapsed`，默认展开）。 |
| `records` | 计时记录数组，**最多保留最近 500 条**，超出丢弃最旧的。 |
| `session:<练习路径>` | 进行中的题目会话，用于关闭页面后续接；超过 12 小时自动清理。 |

**记录里包含**：题目在练习中的位置、本地题目指纹、练习路径、开始/结束时刻、
用时、暂停时长、是否超时、第一次提交的时刻与对错、结束原因、识别置信度。

**记录里不包含**：题目原文、你输入的答案、账号信息，或任何与计时无关的数据。
题目文本只在内存中临时用于生成本地指纹（一个 8 位十六进制短哈希），**不落盘**。

### 清除

- 打开弹出面板 → **清除全部记录**。这只会删掉 `records`，设置保持不变。
- 想连设置一起重置：在弹出面板把各项调回默认值，或卸载后重新加载扩展。

### 查看

弹出面板底部的「本地记录」区域会列出最近 10 条，包含用时、模式、是否超时、
第一次提交的结果与题目短标识。

## 开发

```bash
pnpm install

pnpm run build          # 一次性构建到 dist/
pnpm run build:watch     # 监听源码变化自动重建
pnpm run typecheck       # tsc --noEmit，严格模式
pnpm run test            # vitest run
pnpm run test:watch      # vitest 监听
pnpm run icons           # 重新生成图标 PNG
pnpm run verify          # typecheck + test + build + dist 检查
pnpm run verify:edge     # 真实 Edge 端到端验证（67 项）
pnpm run verify:all      # 上面两个一起跑
```

`src/` 与 `dist/` 严格分离：**Edge 只加载 `dist/` 里编译后的 JavaScript**。

构建**刻意不做压缩**，并同时输出 source map。这样需求 8.4「代码审查确认没有计时数据
上传」可以直接对着 `dist/*.js` 人工审查。

## 测试与验证

本项目提供三层可执行的验证，全部可以一条条重跑。

### 1. 单元测试

```bash
pnpm run test
```

181 个用例，覆盖：

- **计时引擎**（`tests/timer-engine.test.ts`）：从时间戳计算用时、暂停/继续、
  大跨度时钟跳跃（模拟休眠一小时）、倒计时精确归零时刻、超时只提示一次、
  模式切换、第一次提交时间戳只记一次、跨页面重载恢复、格式化。
- **题目识别**（`tests/question-detector.test.ts`）：
  - 纯决策逻辑：去抖、冷却、重复事件抑制、A→B→A 抖动不切换、
    找不到区域/无身份时保守降级、显式导航立即切换、`Start over` 强制重题。
  - DOM 适配（jsdom + 复刻真实结构的 DOM）：按进度索引识别、按状态段不误判、
    候选需要自行复核确认、区域消失时不重置计时。
  - **回归用例**（对应验收标准 8.3）：输入答案、答错浮层、**提示展开使区域文本
    从 3.5 KB 涨到 23 KB**，都不得重置计时。
  - 站点工具：进度解析、`exerciseKey` 解析、提交对错判定。
- **本地存储**（`tests/storage.test.ts`）：设置往返、记录上限与新旧淘汰、
  数据损坏时的清洗、清除记录不影响设置、会话 TTL、存储读写失败时的降级。
- **结束页与「本轮」模型**（`tests/summary-view.test.ts`）：一轮练习的识别与过期、
  只取本轮的记录、旧版本记录（无 runId）的兼容、卡片插入位置、跳过/超时/答对/答错
  标记、空状态、重复渲染不叠加、Shadow DOM 样式隔离、销毁清理。

### 2. 构建产物检查

```bash
node scripts/verify-dist.mjs
```

**56 项检查**，把若干验收标准变成机器校验：

- `manifest.json` 可解析、是 Manifest V3、必填字段齐全；
- manifest 引用的每个文件都真实存在；
- **权限严格在允许清单内**（`storage`、`activeTab`），没有 `host_permissions`、
  没有 `optional_permissions`、没有 background worker、没有 `web_accessible_resources`；
- 内容脚本只匹配 `khanacademy.org`，没有 `<all_urls>`；
- **`dist/*.js` 中不存在** `fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` /
  `sendBeacon` / `eval` / `new Function` / `importScripts` / 动态插入 script /
  外部 http(s) 地址 —— 这是「没有计时数据上传、没有远程代码」的机器证明；
- 图标是真实 PNG 且尺寸与声明一致；
- `dist/` 中没有意料之外的文件。

### 3. 真实 Edge 端到端验证

```bash
pnpm run verify:edge
# 等价于 node scripts/verify-extension.mjs
```

把 `dist/` 作为解压扩展加载进真实 Edge，打开真实练习页，通过 CDP 驱动，
直接从面板的 Shadow DOM 读取数值。

**74 项检查**（少数检查依赖该轮实际出现的题型，例如没有加试题时那一项会标为
inconclusive，因此总数会略有浮动），包括：面板注入与 Shadow DOM 隔离、正计时自动开始、数值随时间增长、

## 题目识别原理

这一节解释「为什么这样识别」，完整的实测证据见 `references/`。

### 题目区域

优先取 `form[name="answerform"]`（Perseus 渲染器把整道题都放在这个表单里），
依次降级到 `.framework-perseus`、`.perseus-renderer`。

实测（真实页面、真实答题）：**提交答案前后，该区域的文本逐字节相同**，
答对/答错的反馈浮层是它的**兄弟节点**而非子节点，因此答题反馈不会干扰识别。

### 题目标识 = 题目进度索引

练习页底部每个进度点带一个 testid：

```
exercise-progress-<索引>-<状态>[-current]
```

实测结论：

- **索引**在切题时变化（`0 → 1 → 2 → 3`）；
- **状态**（`incomplete` / `correct` / `incorrect`）在**提交答案时**变化。

所以身份只取**索引**。如果把整个 testid 当身份，学生每提交一次答案就会被判定为换题。
站点**不提供**单题稳定 id（`data-question-id` 等全部 0 次匹配），因此这是最强可用信号。

若页面没有进度标记（未验证的页面类型），降级为「题干文本 + 题型签名」的哈希指纹，
并把置信度标为较低，面板会显示出来。

### 提示与解答不会重置计时

实测发现：展开提示/分步解答时，内容会渲染**在题目区域内部**，区域文本从 3,466 字符
暴涨到 22,910 字符，但**进度索引没有变化**。

由于身份是索引，这种情况天然不会误判。这一点已写成回归测试长期锁定。
（另外 `[role="dialog"]` / `[role="alert"]` / `[aria-live]` 会从指纹中剔除作为冗余防护。）

### 去抖与重复抑制

新身份必须**连续稳定 400 ms**、且距上一次已接受的切换**至少 1200 ms**，才会被接受。
同一道题只会有一次切换事件，因此不会产生重复记录或多重计时器。
候选出现后检测器会主动安排一次延后复核来确认它 —— 这个「第二次观察」是必须的，
否则候选会永远停在待确认状态（这正是真实页面验证抓出来的缺陷之一）。

### 不确定时的行为

找不到题目区域、或没有任何可用身份信号时：

1. 发出 `uncertain` 事件；
2. **保持当前计时不变**（不重置）；
3. 面板显示黄色警告，说明可以用「重置本题」手动开始；
4. 面板的「识别」一栏显示「未识别 / 弱信号」。

### 显式重置信号

- **URL 变化**：清空识别状态，按新页面重新开始。
- **点击「Start over」**：视为该题被就地重新生成，强制开始新题计时
  （因为索引不变，自动检测无法发现这种情况）。

## 故障排查

### 面板没有出现

1. 确认当前页面的域名是 `khanacademy.org`（扩展只在这些域名注入）。
2. 到 `edge://extensions` 确认扩展已启用，且**没有报错**。
3. 确认地址是**练习页**（URL 里含 `/e/`、`/quiz/` 或 `/test/`）。
   课程目录页、视频页没有题目区域，因此不会显示面板。
4. 刷新页面（内容脚本在页面加载后注入）。
5. 打开弹出面板看诊断信息：若「当前状态」显示「未找到题目区域（此页面暂不支持）」，
   说明该页面结构尚未适配。

### 面板显示「识别：未识别」或出现黄色警告

说明页面结构与已验证的练习页不同。此时**计时会保持不变**，不会乱重置 ——
这是刻意的保守行为。请用「重置本题」手动开始新题计时。
如果希望适配，请把弹出面板「诊断信息」里的内容（命中的策略、错误列表）反馈出来。

### 切题后计时没有重置

1. 打开弹出面板看「置信度」。如果是「弱信号」或「未识别」，说明该页面没有
   可用的进度标记。
2. 确认页面底部确实有题目进度点（`Do N problems` 旁边的圆点）。
3. 如果该练习是「Start over」后重新生成的，点击「重置本题」也可手动开始新计时。

### 倒计时没有声音

浏览器会在用户与页面交互之前阻止音频播放。点击页面任意位置后再试。
面板会在页脚说明提示音被阻止。

### `pnpm run test` 报 Rollup 原生模块加载失败

症状：

```
Error: Cannot find module @rollup/rollup-<platform>
...
ERR_DLOPEN_FAILED ... different Team IDs
```

原因：Vitest 依赖的 Rollup 会加载平台原生模块，而某些环境（例如 Node 二进制以
macOS **hardened runtime** 签名运行）会因签名 Team ID 不同而拒绝加载该模块。

本仓库已在 `pnpm-workspace.yaml` 中把 `rollup` 覆盖为**纯 WebAssembly 版本**
（`@rollup/wasm-node`），API 完全一致且不依赖原生模块，因此默认不会有这个问题。

如果不小心装回了原生版本：

```bash
rm -rf node_modules pnpm-lock.yaml
pnpm install
```

（若你确实希望使用原生 Rollup —— 例如在不受该签名限制的环境里追求速度 ——
删掉 `pnpm-workspace.yaml` 中的 `overrides` 一段再重装即可。）

### `pnpm run build` 之后 Edge 里没有变化

Edge 不会自动感知 `dist/` 的变化。到 `edge://extensions` 点击扩展卡片上的
**重新加载** 图标，然后刷新可汗学院页面。

### 不想让它记录我的练习数据

- 计时记录只存在本机，永远不会上传（可用 `node scripts/verify-dist.mjs` 复核）。
- 用弹出面板的「清除全部记录」随时删除。
- 也可以关闭「关闭页面后重新打开时继续上次用时」，这样就不会写入进行中的会话。
