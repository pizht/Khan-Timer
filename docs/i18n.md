# 多语言（i18n）设计与操作说明

本文件说明本扩展的多语言方案：**英文（`en`）是默认语言、消息键的真源与兜底语言，
简体中文（`zh-CN`）是译文**。当前只发这两种语言，新增第三种语言的步骤见文末。

目标读者是维护者。用户视角的说明在 [README → 设置说明 → 语言（多语言）](../README.md#语言多语言)。

---

## 1. 为什么不用 `chrome.i18n` 做全部工作

Manifest V3 自带 `_locales/` + `chrome.i18n.getMessage()`，本方案**只在它不可替代的地方**
使用它，其余走自带的消息目录。理由：

| 关注点 | `chrome.i18n` | 自带目录（本方案） |
|---|---|---|
| 扩展名 / 描述本地化（管理页、商店） | ✅ 唯一手段 | ❌ 覆盖不到 |
| HTML 里的静态文案 | ❌ MV3 **不支持** HTML 中的 `__MSG_key__`（只在 manifest 与 CSS 生效） | ✅ `data-i18n` + 运行时替换 |
| 应用内切换语言 | ❌ 没有「强制指定语言」的 API，只能跟随浏览器 UI 语言 | ✅ 存进设置，随时改 |
| 单元测试（vitest/jsdom） | ❌ 没有 `chrome.i18n`，每个测试都要 mock | ✅ 纯函数，直接测 |
| 漏译 | ❌ 运行时静默返回空串 | ✅ 编译期报错 |

因此：**`_locales/` 只放扩展名与描述**（`extName` / `extDesc`），界面文案一律走
`src/i18n/`。两者内容不重叠，不存在同一句话维护两遍的问题。

## 2. 目录与职责

```text
src/i18n/
├── en.ts       # 英文目录：唯一真源。MessageKey = keyof typeof en
├── zh-CN.ts    # 简体中文：Record<MessageKey, string>，少一个键就编译不过
├── index.ts    # t() / setLocale() / resolveLocale() / 复数选择 / 插值
└── dom.ts      # localizeDom()：把 popup.html 的 data-i18n 节点翻成当前语言
public/_locales/
├── en/messages.json      # default_locale，扩展名与描述（英文）
└── zh_CN/messages.json   # 同上（中文）
```

### 键的命名

按界面分区加前缀，便于查找与增删：`app.*`（共用）、`overlay.*`（悬浮面板）、
`summary.*`（结束页卡片）、`event.*`（面板页脚 / 弹出面板的「最近事件」）、
`warning.*`（降级提示）、`popup.*`（弹出面板）。

### 占位符与复数

- 占位符写作 `{name}`，由 `t()` 插值：`t('summary.questionNumber', { number: 3 })`。
  参数缺失时**保留占位符原文**（`Question {number}`），让 bug 看得见，而不是渲染成空。
- 需要随数量变化的消息写成 `_one` / `_other` 两个键，调用时传 `count`，
  由 `Intl.PluralRules` 按语言选择：

  ```ts
  'summary.totalAll_one': '{count} question · {total} total',
  'summary.totalAll_other': '{count} questions · {total} total',
  ```
  ```ts
  t('summary.totalAll', { count: rows.length, total: formatDuration(totalMs) })
  ```

  `t()` 接受的是**基名**（`summary.totalAll`）。`PluralKey` 由目录自动派生：
  只要目录里有 `X_one` / `X_other`，`X` 就能当键用；没有复数兄弟的基名会被编译器拒绝。
  中文只有一个复数类别（永远命中 `_other`），因此 `_one` 与 `_other` 文案相同 —— 两个都写，
  是为了让类型保持「全量覆盖」，也提醒译者这个键与数量有关。
  查找顺序是「本语言的目标类别 → 本语言的 `_other` → 英文的 `_other`」，
  所以将来加俄语这种多类别的语言时，缺 `_few` 也会退回一句通顺的话，而不是露出键名。

- **不要往文案里塞 HTML**：`t()` 只返回纯文本；`overlay.ts` / `summary-view.ts`
  自己拼模板并在需要处 `escapeHtml`。

## 3. 语言是怎么选出来的

```
settings.language = 'auto' | 'en' | 'zh-CN'      （默认 'auto'）
        │
        ├─ 'en' / 'zh-CN' ──────────────► 就用它
        └─ 'auto' ─► chrome.i18n.getUILanguage() ─► navigator.language ─► 归一化
                                                          │
                            'zh*' → zh-CN ；'en*' → en ；其它 → en（兜底）
```

- 归一化只看语言前缀、丢掉地区：`en-US` / `en-GB` → `en`；`zh-Hans-CN` / `zh-TW` → `zh-CN`。
- **查不到的语言一律回落英文**（`FALLBACK_LOCALE`），因为目标用户以英语母语者为主；
  单个键在译文里缺失时也回落英文。
- 用户可在弹出面板的 `语言` 里固定一种，值存进 `chrome.storage.local` 的 `settings`。
  存旧值时 `sanitizeSettings` 会把无法识别的值归为 `'auto'`（`storage.ts`
  的 `sanitizeLanguage`），**老版本写下的设置不需要迁移**，缺失的 `language` 键也一样。

### 切换语言后，界面上已经有的字怎么办

这是最容易出错的一处，分三类处理：

1. **`popup.html` 的静态文案**：`data-i18n="<key>"` + `localizeDom()` 重扫一遍。
   注意 MV3 不允许在 HTML 里用 `__MSG_`，所以必须走这条路；HTML 里写着的英文
   是源语言与兜底文案，`tests/i18n.test.ts` 会断言它与 `en.ts` 完全一致，防止漂移。
2. **面板 / 卡片自身的标签**（标题、按钮、`aria-label`、以及 CSS 伪元素画的
   「已完成 / 已暂停」徽标）：`OverlayView.applyLanguage()` 与
   `SummaryView.applyLanguage()`。伪元素那句文案是通过重建 `<style>` 的
   `textContent` 更新的 —— 它不在 DOM 文本节点里，改 textContent 够不着。
3. **面板页脚的状态行与降级提示**：它们**不存翻译好的字符串**，只存
   `MessageRef = { key, params }`，在真正绘制时（`render()` 里的 `lastEventText` /
   `warningText` 取值器）才翻译。否则切换语言后，这行字会一直停在旧语言，
   直到下一次识别事件碰巧覆盖它。

`controller.ts` 监听 `chrome.storage.onChanged`：`language` 变化时 `setLocale()` 并让
面板与卡片 `applyLanguage()`，因此**不需要刷新页面**，正在答题的页面也会立刻改文案。
计时状态机完全不参与这件事（见下文第 5 节）。

## 4. 验证

| 手段 | 覆盖什么 |
|---|---|
| `pnpm run typecheck` | 译文缺键、键名拼错、`PluralKey` 用法错误 |
| `tests/i18n.test.ts` | 目录键集一致、无空文案、无「照抄英文」的漏译、占位符两边一致、复数按语言选择、回落与归一化、`data-i18n` 键存在且与英文一致、被标记的节点都是叶子节点 |
| `tests/popup.test.ts` | 语言选择器：选项、切换后**重排文案**（含由数据生成的状态行与记录条数）、`<html lang>`、写入存储、下次打开沿用 |
| `tests/overlay.test.ts` | 面板切换语言：标题 / 按钮 / `aria-label` / **CSS 伪元素徽标** |
| `tests/summary-view.test.ts`、`tests/controller.test.ts` | 改为对着消息目录断言，不再和界面语言绑死 |
| `verify-dist.mjs` | `_locales/` 必须声明 `default_locale`（否则浏览器直接拒绝加载）、manifest 里每个 `__MSG_*__` 都能解析出非空文案、商店描述 ≤ 132 字符、`dist/` 白名单放行 `_locales/**/messages.json` |
| `scripts/verify-extension.mjs` | 真实 Edge：面板按预期语言渲染（1b 项），以及语言选择器的**双向**端到端验证（选 English → 弹出面板与**页面内面板**都改文案；选回「跟随浏览器」→ 恢复） |
| `scripts/verify-practice-switch.mjs` | 真实 Edge：开跑前把 `settings.language` 固定为 `zh-CN` |

### 两个端到端脚本为什么要「固定中文」

它们读的是**中文文案**（`正计时`、`继续`、`第 N 题`、`数据缺失`、`加试`、
`暂停 0:17`…）。界面语言改成跟随浏览器后，这些断言就会随运行机器而变，所以：

- `verify-extension.mjs`：启动参数加 `--lang=zh-CN`，并**另外**通过扩展自己的存储写入
  `language: 'zh-CN'`（`pinLanguage()`），因为 `--lang` 并非所有平台都生效；
  第 1b 项检查断言的是**面板标题**（真正被读取的东西），不是浏览器的语言。
- `verify-practice-switch.mjs`：只用 `pinLanguage()`，因为 `--login` 会复用带
  locale 的既有 profile，命令行参数不保证赢过 profile 里的偏好。
- `verify-startcard-flash.mjs` 不断言任何界面文案（它只看计时数字与面板可见性），
  因此不需要固定语言。

### 手工验证

1. 打开弹出面板，把 `语言` 切到 `English`：面板上的标签、状态行、历史记录立刻变英文，
   `<html lang="en">`。
2. 在**已经打开并正在计时**的 Khan Academy 页面上做同样的切换：悬浮面板的标题、
   按钮、`限时/进度` 等 meta、页脚的「最近事件」都应立刻变英文（不必刷新页面）。
   开发者模式下还能看到结束页卡片同样跟着变。
3. 切回 `跟随浏览器`：浏览器界面语言是中文时，应恢复中文。

## 5. 边界与不做的事

- **不翻译代码注释、`console.warn` 与诊断用的原始数据**。诊断块（开发者模式）里
  的字段名已翻译，值（选择器策略名、`data-testid`、题目标识）保持原样，因为它们是
  用来对照排查的标识符。
- **不翻译站点文本**。`site-profile.ts` 里对页面文字的判断（如隐私横幅的
  `cookie|privacy|隐私`）是**匹配页面**用的，不是界面文案，绝不能跟着界面语言走。
  题目对错取自进度状态段而非提示文字，因此识别逻辑与界面语言无关。
- **`Intl` 只用于复数与时间格式**。记录里的时间用 `toLocaleTimeString(getLocale())`
  按所选语言格式化；时长（`m:ss`）是语言无关的，不格式化。
- **商店列表**（Chrome Web Store / Edge Add-ons 的名称、描述、截图说明）要在开发者
  后台单独填，`_locales` 管不到那部分。

## 6. 新增一种语言（例如日语）

三步，全部有编译期或测试期保护：

1. **加译文**：复制 `src/i18n/zh-CN.ts` 为 `src/i18n/ja.ts`，改成
   `export const ja: Record<MessageKey, string> = { ... }`。
   少一个键 → `pnpm typecheck` 报错；键名写错 → 同样报错。
2. **注册**：`src/i18n/index.ts`
   - `CATALOGS` 加一行 `ja`（`SUPPORTED_LOCALES` 由它派生，不用单独维护）；
   - `normalizeLocale()` 加一条前缀判断（`lower.startsWith('ja')`）。
3. **界面与清单**：
   - `src/types.ts` 的 `Locale` 联合类型加 `'ja'`；
   - `public/popup.html` 的语言下拉框加一行
     `<option value="ja">日本語</option>`（语言名用它自己的语言写，不加 `data-i18n`）；
   - `public/_locales/ja/messages.json`（内容照抄 `en`，翻译 `extDesc`；
     `extName` 是产品名，保持不译）。
4. 跑 `pnpm run verify`：`tests/i18n.test.ts` 会自动把新目录纳入
   「键集一致 / 无空文案 / 占位符一致 / 已翻译」这四条检查，`verify-dist.mjs`
   会放行新增的 `_locales/ja/messages.json`。

如果译文由不懂 TS 的人提供，可以再加一个 build 期 codegen（`locales/ja.json` →
`src/i18n/ja.ts`）。当前两种语言还不值得增加这一层。
