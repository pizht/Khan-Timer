# 已知限制清单

本文件是需求文档「交付物」第 8 项。每条都说明**限制是什么、为什么、影响多大、
以及当前的应对**。不含粉饰。

---

## 1. 连续切题次数未达到验收标准要求的 10 次

- **限制：** 验收标准 8.3 要求「对已验证的每种页面类型，至少测试连续完成 10 次题目切换」。
  本版本实际完成 **3 次**（未加载扩展的交互采集，进度索引 0→1→2→3）
  与 **1 次**（加载扩展的端到端验证）。
- **原因：** 用于验证的练习只有 4 题（页面标注 `Do 4 problems`），
  且每次切题都必须先答对；自动化的连续切题上限受题量限制。
  达到 10 次需要在多套练习上人工连续操作，本次未做。
- **影响：** 中等。切题机制本身已被真实驱动验证（索引正确递增、旧题记录被保存、
  新题计时重新开始、题目标识随之变化），但**长序列的稳定性（例如第 7、8 次切题是否
  仍然正确）没有实测证据**。
- **应对：** 已用单元测试覆盖重复事件的抑制、去抖、冷却与抖动场景；
  建议在正式发布前人工在多套练习上补齐 10 次连续切题的记录。

## 2. 只深度验证了一种题型（数值输入）

- **限制：** 深度验证的只有 `perseus-input` 数值输入题。
  选择题、表达式输入、下拉题、拖拽题、交互图等**未实际观测其 DOM**。
- **原因：** 采集时间与范围有限；需求文档也要求不要把未观测的结构写成选择器。
- **影响：** 中等。这些题型大概率可用同一套识别（题目区域与进度标记是练习页级别的，
  与题型无关），但**未经证实**。
- **应对：** 题型签名（`ANSWER_WIDGET_MARKERS`）已按通用标记（radio / checkbox /
  select / contenteditable / role=radio 等）实现，不依赖具体题型；
  识别不可靠时会保守降级。

## 3. 只验证了未登录状态

- **限制：** 全部采集与验证都在**未登录**状态下完成。登录后的课程进度、指派作业、
  已完成练习等页面**未观测**。
- **原因：** 需求文档明确要求不索取用户密码、Cookie、令牌或完整浏览器配置文件。
- **影响：** 未知。登录态可能改变部分页面结构（例如新增导航、进度提示）。
- **应对：** 需求文档第 3 节「处理登录限制」允许后续用用户自己已登录的 Edge
  做脱敏采集；当前未做。

## 4. 只验证了 `www.khanacademy.org`

- **限制：** 未访问 `es.`、`pt.` 等本地化站点，也未访问其他课程。
- **影响：** 低。识别方案不依赖界面文案（题目标识取自 `data-testid` 的索引，
  答题对错取自进度状态段而非提示文字），因此理论上与语言无关。
- **应对：** `manifest.json` 的匹配范围包含 `https://*.khanacademy.org/*`，
  本地化站点会注入并尝试识别。

## 5. 提示 / 解答容器的稳定选择器未确定

- **限制：** 页面上有 "Hints" 文案，但按文案查找 Hint 展开控件**未命中**；
  提示内容只通过 Skip 确认框间接触发过。因此 `HINT_SUBTREES` **留空**。
- **原因：** 需求文档要求「不要猜测未观察到的页面结构」，因此没有编造选择器。
- **影响：** 低（在当前架构下）。题目标识是**进度索引**，而实测证明提示展开时
  索引不变，因此提示展开**天然不会**被误判为切题。
  该场景已写成回归测试锁定。
- **影响范围说明：** 只有在**没有**进度标记的页面类型上（即未验证的页面类型），
  才会退回文本指纹路径；此时展开提示确实可能改变指纹。
  该路径下面板会把置信度标为较低，并显示可见降级提示。

## 6. 「Start over」的语义未实测

- **限制：** 点击 `start-over-button` 后是否在同一进度索引上生成**新**题目，
  **未驱动验证**。
- **影响：** 中。由于题目身份是进度索引，如果新题沿用同一索引，自动检测**无法**发现。
- **应对：** 已按「会生成新题」实现：监听 `start-over-button` 点击，
  强制为新题并重新开始计时（`decider.reseed()`），并有单元测试覆盖。
  若实际语义不同（例如只是清空答案、题目不变），则该次点击会错误地重新开始计时
  —— 这是当前已知的、可能的误判点。

## 7. 电脑休眠 / 长时间后台未做实测

- **限制：** 未在真实机器上做休眠实测。
- **影响：** 低。计时完全基于时间戳差分，不依赖定时器触发次数。
- **应对：** 单元测试覆盖「一小时没有触发任何 tick」的场景，
  断言用时与倒计时归零时刻都按真实时间计算。

## 8. 未验证「上一题」导航

- **限制：** 已验证的练习页**没有**上一题控件，因此该路径未验证。
- **影响：** 低。若页面提供，检测器会把索引变化当作一次可靠的题目变化处理。
  但「回到已经记录过的题」会再生成一条新记录（而不是合并到旧记录），
  因为本项目不做跨会话的记录合并。

## 9. 记录上限 500 条，超出即丢弃最旧的

- **限制：** `records` 最多保留 500 条，更早的会被静默丢弃。
- **原因：** 避免本地存储无限增长。
- **影响：** 低。按每题一条计，500 条足以覆盖长期使用。

## 10. 关闭页面期间的语义是「冻结」

- **限制：** 关闭页面后重新打开同一题时，关闭期间的时间**不计入**用时。
  这与「标签页隐藏 / 电脑休眠时按真实时间计算」不同。
- **原因：** 需求 2.2 只说「保留计时数据，在下次重新做本套题目时继续使用之前的数据」，
  未明确规定关闭期间算不算。判断是：关闭页面时学生并未在作答，因此冻结更符合直觉。
- **影响：** 中。这是一个**产品决策**，可能需要与需求方确认。
  如果希望关闭期间也计入，需要改变 `TimerEngine.restore()` 的语义。
- **可关闭：** 弹出面板有「关闭页面后重新打开时继续上次用时」开关，
  关闭后每次都从零开始，也就不会产生这个问题。

## 11. 会话有效期 12 小时

- **限制：** 进行中的题目会话超过 12 小时会被丢弃，不再续接。
- **影响：** 低。避免隔天恢复出奇怪的用时。

## 12. 面板可能遮挡页面元素

- **限制：** 面板默认固定在右上角，可能与页面右上角的元素重叠。
- **应对：** 面板**可拖动**且**可折叠为小胶囊**，位置会被记住
  （需求 2.3 允许先提供固定位置与折叠功能）。
  弹出面板中也可以直接隐藏面板。

## 13. 未做浏览器跨版本兼容测试

- **限制：** 只在 Microsoft Edge **154.0.4258.62** 上验证。
- **原因：** 需求文档第 7 节要求「以开发和验收时的当前稳定版 Microsoft Edge 为目标」。
- **应对：** 构建目标为 `chrome114`，`manifest.json` 声明
  `minimum_chrome_version: 114`。

## 14. 计时的秒级精度

- **限制：** 面板显示到秒（需求 2.2 写明「精度以秒为主」）。
- **说明：** 内部以毫秒存储与计算，只是显示取整。短于 1 秒的题目切换会显示 `0:00`。
- **相关：** 时长不足 1 秒且没有提交记录的会话，会被视为识别噪声而**不写入记录**，
  以免产生大量无意义条目。

## 15. 「本轮每题用时」只在未登录的结束页上验证过

- **限制：** 结束页表格的**插入位置**只在**未登录**状态下验证过。
- **原因：** 未登录时结束页有一张 `data-testid="eot-phantom-user-registration"`
  的卡片（名字里的 `phantom-user` 就是指未登录用户），表格被插到它的评分行下方。
  登录用户的结束页很可能没有这个 testid。本次采集全程未登录，且不索取凭证，
  因此**登录态的结束页结构未观测**。
- **影响：** 中。结束页的**判定**用的是结构不变式（没有答题表单 + 练习外壳仍在），
  这个与登录与否无关，已在 6 个采集阶段逐一验证；只有**插入位置**可能在登录态下不同。
- **应对：** 插入位置有三层降级：结束页卡片 → `.bibliotron-exercise` → 外层练习面板。
  前一层不存在时会退到下一层，因此登录态仍会显示表格，只是位置可能不在评分行下方。

## 16. 有 bonus question 的练习：表格里会出现「加试」行

- **行为：** 有些练习（例如验证用的 `addition_4`）在最后一道普通题之后还有一道
  **加试题**，控件文案是 `Bonus question`，进入后进度索引**从 0 重新开始**。
- **实现：** 结束页表格按**题号**编排（记录在开始计时时就带着自己的题号），
  没有计时数据的题号写「数据缺失」；页面索引倒退的那一行（加试题）排在编号题目之后并
  标记「加试」。这样表格里不会出现两个「第 1 题」。
- **限制：** 只观测了 `addition_4` 这一种加试题形态；加试题是否可能有多道、
  或是否有不同的交互结构，**未验证**。
- **影响：** 低。「加试」只是一个标记，计时与识别逻辑与普通题完全一致。

## 17. 「Try again」后是否真的开始新一轮，未单独验证

- **行为：** 结束页消失时（点击 `Try again` 或重新打开练习），扩展会清空本轮记录，
  下一次答题算作新一轮。
- **限制：** 结束页出现后点击 `Try again` 的完整往返**未在真实页面上驱动验证**。
  实现依赖的是 `isSummaryPage` 由真变假这一结构变化。
- **影响：** 低。极端情况下若结束页消失但结构判定没跟上，新一轮可能被并入上一轮，
  表现为表格里多出几行。再点一次 `Try again` 或刷新页面即可恢复。

## 18. 停表后必须切题（或离开练习）才会写入记录

- **行为：** 答对或跳过后计时立即停止，但**记录要等题目真正切换（或结束页出现、
  或离开这个练习）才写入**。这是有意的：结束页需要最后一题的用时，所以记录必须先
  留在手里。
- **限制：** 如果学生在停表后**直接关闭页面**，这条记录会通过 `pagehide` 的检查点
  保存为进行中的会话，但**不会立刻成为一条已完成记录**；下次打开同一题时会继续，
  而不是生成一条记录。切换练习/离开页面（页面没有重新加载的单页应用跳转）时会立刻
  落盘，见第 21 条。
- **影响：** 低。不会丢失时长，只是记录的落盘时机推迟。

## 19. 未识别时面板不显示**且计时暂停**，原因只在弹出面板里可见

- **行为：** 题目识别失败（面板「识别：未识别」）时**不显示**悬浮面板，并且把本题计时
  **暂停**——这段读不出来的时间不计入本题。两者都是用户明确要求的。
- **数据保留：** 暂停**不是**丢弃：`TimerEngine` 实例、已累计用时、第一次提交时间戳与
  本轮 `runId` 都保留。重新识别到**同一道题**时从暂停值继续；识别到的是另一道题则正常
  结算。因此被暂停的那道题**仍然会生成记录，仍然出现在结束页的用时统计里**。
- **权衡（可见提示的落点）：** 面板已隐藏，因此「无法可靠识别」的可见提示只出现在
  **扩展弹出面板**里（需要点一下工具栏图标，文案为
  `未识别到题目：本题计时已暂停，重新识别到本题后自动继续`）。
  需求 8.3 要求「提供可见提示**或**可用的手动恢复方式」——本实现选前者，但落点在
  弹出面板而非页面内。好处是页面不被一个量不出东西的时钟干扰，且这段时间不会被计时；
  代价是用户需要主动点开面板才知道「这个页面为什么突然不计时了」。
- **副产物：** 暂停的这段时间累加进这道题的 `pausedMs`，所以结束页那一行会多出一行
  小字 `暂停 0:31`。记录的 `wasPaused` 仍只表示「**学生**按过暂停」，自动暂停不会
  把它置为 true。
- **页内警告的生命周期（已修复的用户报告）：** 页面上那条
  `无法可靠识别当前题目（question region not found）。本题计时已暂停…` 只在
  **面板可见且页面确实读不出题目**时渲染，并在**同一道题重新被识别**时立即清除
  （`ContentController.clearIdentityWarning()` + `OverlayView.render()` 的
  `state.warning && panelVisible` 判断）。
  修复前它一旦写入就只在下一次 `beginQuestion` / 重置本题 / 结束页 / 切换练习时消失，
  于是 SPA 为几百毫秒替换题目子树所造成的一次瞬时 `uncertain`（时钟随即自动恢复）
  会在**正在计时的面板上**留下这条过期警告——用户报告为「与现实不符」。
  回归用例：`tests/controller.test.ts` →
  `does not keep the not-found warning after the same question is identified again`、
  `keeps the warning only while the page really cannot describe a question`。
- **影响：** 低。若希望页面上也有提示，可以另行确认（例如显示一个极简的静态小图标）。

## 20. 面板只在计时中出现，题目出现前不可见

- **行为：** 测验 / 单元测试 / 课程挑战需要先点介绍卡片上的 `Let’s go`，
  题目出现后面板才显示。
- **影响：** 低，但需知晓：在这类页面上，点击 `Let’s go` 之前面板不会出现，
  这是预期行为（那时还没有题目）。
- **未验证：** 课程挑战（30 题）与单元测试（10 题）只验证了「开始后能识别、面板出现」，
  没有完整走完全部题目；加试题、结束页在超长题量下的表现未验证。

## 21. SAT test-prep 只验证了结构与面板显隐

- **限制：** 对 SAT test-prep 的四类页面，验证到「识别到题目、面板出现、
  `进度 1 of N 识别：题目ID`」为止。**没有**在这些页面上完整做题、切题、
  验证结束页表格。
- **影响：** 中。这些页面开始后的 DOM 与已验证练习页结构一致（同一套
  `answerform` / `exercise-progress-*` / `check-answer`），因此切题与结束页
  大概率同样适用，但**没有实测证据**。
- **应对：** 选择器完全复用，没有为 SAT 页面写任何特例；若结构实际有差异，
  弹出面板的诊断信息会显示实际命中的策略与错误。

## 22. 切换练习的暂存只覆盖「当前这道题」，且未在真实页面上跑过

- **行为：** 离开一个练习时，本题的会话按 `session:<练习路径>` 冻结保存；回到**同一道题**
  时接着已累计的用时继续。已经答对/跳过的那道题会在离开时立刻落盘。
- **本轮保证（已由测试守住）：** 换练习**不会**开始新的一轮，卡片取数先按练习路由
  （`exerciseKey`）再收到本轮，所以回到练习做完整轮后，结束页仍按**题号**列出切换前
  那几题，用时与对错标记为原值，另一套练习的题目不会混进来；中途被打断的那道题，
  切换前后的用时都算在它自己头上。某个题号没有计时数据时写「数据缺失」，
  不会把下一题的用时顶到它的题号上。记录落盘走单条串行队列（`createRecordQueue`，
  读取前 `flush`），避免 `records` 的「读-追加-写回」在并发时互相覆盖（那正是卡片
  少一行的成因）。
- **限制 1：** 一个练习同时只保留**一道**进行中的题。如果回到练习时页面停在**另一道题**
  （例如可汗学院自己前进了一题），旧题那份会话不会被续接，会在 12 小时后过期清理；
  该题也因此不会生成记录（它本来就没做完）。
- **限制 2：** 练习身份来自地址（`/…/e|quiz|test/<slug>`，路径无对应段时用整个路径）。
  如果两个练习共用同一地址，扩展无法区分它们；这种情况未观察到。
- **未验证：** 该行为由 jsdom 单元测试覆盖（`tests/controller.test.ts`：真实单页应用跳转
  序列 + 内存版 `chrome.storage.local`，含「做完整轮 → 卡片按题号完整」与
  「缺数据的题号写数据缺失」两条端到端用例），**尚未**通过
  `scripts/verify-extension.mjs` 在真实 Edge + 真实可汗学院页面上重跑
  （该脚本会驱动真实站点答题，需要人工环境）。
  上线前建议按 README「测试与验证 → 手动验证」一节手动走一遍：练习 A 做几题 → 切到练习 B
  → 回到 A 做完 → 检查卡片行数、题号与「数据缺失」行。
- **影响：** 低。这一条修的是「切换练习后旧练习的读数跑到新练习上、回来时用时归零」
  的数据丢失路径；上面两条是它的边界条件，都会如实保留在本地会话里，不会污染记录。

## 23. 结束页卡片无法在未登录状态下用真机验证

- **行为：** 结束页卡片只有在可汗学院真的显示了「本轮完成」页时才注入。
- **限制：** 匿名（未登录）用户做完一套练习后，可汗学院把它换成
  「Log in or Sign up to save your future progress!」页面：既没有答题表单，也不是
  结束页（进度点还在、`.bibliotron-exercise` 结构不同），所以扩展不会插卡片。
  这与扩展无关，但意味着**卡片的真机验证必须有一个已登录的会话**。
- **应对：** `scripts/verify-practice-switch.mjs` 支持持久化 `--profile`：
  先用 `--headed` 在弹出的 Edge 窗口里手动登录一次，之后无头重跑即可复用该会话。
  未登录时该脚本仍会验证「换练习不串味」的部分（两个练习各自计时、记录分别归属、
  回到 A 时计时从自己的值继续）。
- **影响：** 低。卡片本身由 jsdom 端到端用例覆盖（真实协调器 + 真实检测器 +
  真实行序模型），真机只差「结束页」这一步 DOM。

## 24. 进度标记晚到会被当成切题（真机复现，已修复）

- **实测：** 在真实页面上，题目区域约在 2.2 s 出现、进度标记约在 3.7 s 出现。
  扩展因此先按**指纹**识别这道题、随后才拿到「第几题（进度索引）」。
- **修复前的表现：** 这次「指纹 → 进度」被当成一次**切题**：当前计时器被结算成一条
  `fp:` 记录（时间短、原因 `question-change`），并立刻新建一个从 0 开始的计时器。
  后果有两个，正好对应反馈里的现象：① 每道题在加载一秒后重新从 0 计时，加载期间
  的用时被写进一条多余记录；② 保存的会话键是进度 id，而刷新/切回时页面先给出指纹，
  键对不上 → **已累计的用时恢复不了**。
- **修复：** 新增 `identity-upgraded` 事件：当「当前身份没有进度位置」而「新身份给出
  进度位置」时，视为**同一道题的身份升级**，计时器不重置、只更新身份并重新写会话；
  会话续接同时接受「题目键相同」或「题干+控件哈希相同」。
- **证据：** 见 `tests/question-detector.test.ts`「upgrades a fingerprint identity…」、
  `tests/controller.test.ts`「a question identified before its progress marker exists」
  两条，以及 `scripts/verify-practice-switch.mjs` 的真机前后记录对比。

## 25. 已登录的 profile 里 Edge 不再加载未打包扩展

- **实测：** 用同一个 `--user-data-dir` 第二次启动 Edge 时，我们的扩展**不再注入**
  （面板不出现、`chrome-extension://…/popup.html` 打开是 `chrome-error://`）。
  原因在 `Default/Secure Preferences` 里：
  `extensions.settings.<id>.disable_reasons = [16777216]`。删掉该条目也无效。
- **应对：** `scripts/verify-practice-switch.mjs` 不再复用已登录的 profile 跑扩展，
  而是用 CDP 把它里面 **khanacademy.org 的 cookies 读出来**（`Network.getAllCookies`），
  在**全新 profile**（扩展必定加载）里 `Network.setCookies` 注入，再打开练习。
  登录态因此保留，不需要每次重新登录。
- **影响：** 只影响自动化脚本的用法，不影响扩展本身。

## 26. 切换练习时旧练习被误判为结束页（真机复现，已修复）

- **实测：** 在应用内从练习 A 点侧栏链接切到练习 B 时，A 的页面会先被拆掉，而这一帧
  「没有答题表单 + 没有进度点 + 练习外壳仍在」——与结束页的结构判据完全一致，只有地址
  已经变成 B。
- **修复前的后果（正是反馈里的现象）：** 扩展把这一帧当成 A 的结束页 → 给 A 的本轮打上
  `summarizedAt` → 随后 `leaveSummary()` 又清掉 A 的本轮记录 → 回到 A 时开始**新的一轮**，
  于是 A 的结束页只列出切换**之后**做的题，切换前那几道的用时（其实仍在存储里）落到了
  上一轮，卡片上显示成「数据缺失」。
- **修复：** `checkPageState()` 进入结束页的条件增加一条——当前 URL 必须仍然属于**本轮
  记录所属的那个练习**（`run.exerciseKey === exerciseKeyFromUrl(location.href)`）。
- **第二道保险（记录检索不再只靠 runId）：** 即使本轮 id 在中途丢了（旧版本的误判、刷新、
  别的写入），记录本身**从来没有被删过**，丢的只是「它属于哪一轮」。所以取数改成三层：
  ① 练习路由（`exerciseKey`）→ ② **本次尝试窗口**（`attempt:<练习路径>` 的 `since`
  时间戳，在每道题开始时开启，只有真的看过结束页才会推进）→ ③ `runId` 兜底。
  窗口让「切换前那几题」永远能被重新检索到，而不必依赖某一轮 id 的稳定性。
- **证据：** `tests/controller.test.ts`「moving to another practice inside the app」与
  「a card built when the attempt id was lost mid-way」（后者把本轮 id 直接删掉再取数，
  没有窗口时会显示「数据缺失」，有窗口时 4 题齐全 —— 用例本身证明了判别力）；
  `tests/storage.test.ts` 的 `attemptRecordsFor` / 窗口用例。
  真机前后对比：修复前卡片是「第 1 题数据缺失 / 第 2 题数据缺失 / 第 3 题 0:05 / 第 4 题 0:06」，
  修复后是「第 1 题 0:09 / 第 2 题 0:07 / 第 3 题 0:04 / 第 4 题 0:14，共 4 题 · 合计 0:36」。
- **历史数据（本版之前）的说明：** 窗口标记是本版才开始写的，所以**本版之前**那次尝试
  不会自动被追认（否则无法区分上一轮与本轮）；那几条记录仍原样留在本地 `records` 里。

## 27. 题目被识别出来之前的「暂停用时」会算到第一题头上

- **现象：** 真机上第 1 题的行会带一行小字「暂停 0:17」，那是页面加载/介绍卡片期间
  计时器处于「未识别」被自动暂停的时间（见第 23 条的功能）。
- **影响：** 只是显示上的观感（这道题并没有被学生暂停过），用时列本身是对的。
  是否把「识别之前的暂停」单独归类，属于产品取舍，未改动。

## 23b. 「识别：未识别 → 暂停 → 同一道题恢复」未在真实 Edge 上驱动验证

- **行为：** 页面给不出可用题目标识时隐藏面板并暂停本题计时；**同一道题**重新可识别时
  从暂停处继续；识别到另一道题则正常结算；中途被暂停的题仍进入结束页统计。
- **未验证：** 浏览器里无法可靠制造出「题目区域被移除、进度标记一动不动、随后同一道题
  原样回来」这一幕——可汗学院真实换题时进度标记会移动，属于另一条已由真实 Edge 覆盖的
  路径（切题结算）。因此这条路径**没有** `scripts/verify-extension.mjs` 的真实检查项。
- **现有证据：** jsdom 端到端测试（`tests/controller.test.ts`）：使用**真实**的
  `ContentController`、`QuestionDetector`、`QuestionChangeDecider` 与 `storage.ts` 逻辑，
  只有浏览器 DOM 与 `chrome.storage.local` 是替身。四条用例分别断言：
  面板隐藏且会话写入 `phase: "paused"`、30 秒不可识别时间不计入本题、同一道题回来后
  `accumulatedMs` 从暂停值接上且 `pausedMs` 累积、学生手动暂停不会被自动继续、
  做完三道题后结束页仍然列出那道被暂停的题（用时与暂停用时分开），
  以及 README 手动验证步骤的逐步复现。
  另有引擎与检测器的定点用例（自动暂停不算「学生暂停」、区域回来即刻重新识别）。
- **应对：** 若要在真实页面上复核，按 `README.md` →「测试与验证」→「4. 手动验证
  「识别：未识别 → 暂停 → 恢复」」里的 DevTools 片段操作（移除题目区域 → 观察面板消失、
  弹出面板显示「本题计时已暂停」→ 原样放回 → 观察面板恢复且读数接着走）。
- **影响：** 低。逻辑为纯状态迁移，且**只在**「识别状态由可用变为不可用再变回同一标识」
  时触发；其余所有计时路径（答对、跳过、切题、切练习、重置、倒计时）都没有改变，
  仍由原有的真实 Edge 检查项与单元测试覆盖。
